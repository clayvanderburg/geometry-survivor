# VEXOLITH // SURVIVOR

A browser-based geometric twin-stick roguelite & asteroid-excavation survival game inspired by *Geometry Wars*, *Deep Rock Galactic: Survivor*, and *Vampire Survivors*.

## Quick Start (Local Dev Server)

```powershell
npm start
```
- **Play Game**: `http://127.0.0.1:8096`
- **Standalone Live Tuning & Dev Sandbox Studio**: `http://127.0.0.1:8096/tuner.html` (or press **`Shift+Alt+T`** in-game, Shift+Option+T on Mac, to toggle the hidden slide-over Tuner Drawer; it has no visible link so the public build stays clean).

## Versions & patch notes

The game has a semver version, `GAME_VERSION` in **`js/version.js`** (the single source of truth), shown as a tag under the title logo, on the pause menu and on the game-over screen. **`js/changelog.js`** holds `CHANGELOG`, the player-facing patch notes, newest first: `{ version, date, title, notes: [{ type: 'new' | 'balance' | 'fix', text }] }`. The **📜 PATCH NOTES** button (title screen and pause menu) opens them; it wears a glowing **NEW** badge until the notes of the current version have been opened (last version read is kept in `localStorage` as `vexolith_patch_notes_seen`; with storage blocked the badge clears for the session only). The notes never open by themselves.

**Rule: every merge that affects gameplay (balance, weapons, enemies, scoring, pacing, anything that changes what a run can score) bumps `GAME_VERSION` and adds a matching entry at the top of `CHANGELOG` in the same PR.** Use a minor bump (`0.9.0` → `0.10.0`) for a release with new content and a patch bump (`0.9.0` → `0.9.1`) for a tuning tweak or fix. Write the notes for players: short, plain and concrete ("Escort Drones fire 4× faster (same damage output)"), no file names or jargon, a handful per version. `tests/changelog.test.js` fails if the version and the newest entry disagree, or if versions are not unique and descending. The global leaderboard is one shared board that never resets: every score is tagged with the version it was set on (see below), so players can see when a run was flown under different balance. Pure UI/docs changes don't need a bump.

**Rule: keep the first-run TUTORIAL accurate.** Any change to something the tutorial says or shows (controls, the shield, mining and veins, gold / reroll / lock, level-ups, weapon slots, lieutenants, bosses, Void Cores / armory) updates its slides in `js/tutorial.js` and, if a clip now looks wrong, re-captures them with `npm run tutorial-media` in the same PR. Every minor version bump (new content) re-checks all slides and sets `TUTORIAL_REVIEWED_FOR` in `js/tutorial.js` to the new major.minor; `tests/tutorial.test.js` fails until it does. Keep it brief: a few short lines per slide. See [Tutorial](#tutorial-first-run-slides).

Versions 0.1.0–0.8.1 were assigned after the fact from the merge history: 0.1.0 the original prototype, 0.2.0 PR #3–#4, 0.3.0 #5–#6, 0.4.0 #7–#8, 0.5.0 #9, 0.6.0 #10–#11, 0.7.0 #12–#13, 0.8.0 #14, 0.8.1 #15, 0.9.0 versioned leaderboard + patch notes.

## Core Mechanics & Features

1. **Geometric Crab Ship with Twin Rotary Drill-Claws (`drawCrabShip` in `js/main.js`)**
   - Wide hexagonal armored carapace with swept delta wings (the hull faces where you fly; only the drill arms swing round to the rock being mined).
   - **Twin Front Rotary Drill-Claws**: Orient automatically toward your movement direction (or snap onto the asteroid rock face you are boring into), clamping inward, spinning helical drill threads, vibrating, and spraying grinding sparks.
   - **360° Independent Plasma Turret**: Rotates toward your aim cursor (`p.angle`) independently of your crab hull.
   - **Prism Split streams** (`PRISM_STREAMS` in `js/weapon-scaling.js`): the blaster starts as two parallel streams straight at your aim. Each Prism Split level adds a pair in a fixed order (rear → sides → forward diagonals → rear diagonals → flanks) without moving existing streams, so the forward pair always stays aimable.
   - **Rocket Pods** (run-start or NEW WEAPON pick, LV 1–18): every 0.5 s while firing, the two wingtip pods launch slow dumbfire rockets where the turret aims (mouse, right stick or auto-aim, same as the Autocannon). Direct hit + small blast; tagged `PROJECTILE EXPLOSIVE AREA`. Launch Rails cards shorten the volley interval, Tubes add rockets (2 → 8 per volley, alternating pods) and Blast Size widens the blast; damage per hit is solved from the shared DPS curve (×1.5, `LV1_TRIM`).
   - **Strict Mining Separation**: Weapons, missiles, orbitals, singularities, and Supernova bombs **never** mine asteroids—bullets spark off rocks as solid cover. **Only your Crab Ship's front Drill-Claws** can carve tunnels through asteroid clusters (the **Claw Harpoon** counts: it throws one of them on a tether; a **Graviton Mortar** with Tidal Shear or Spacetime Fractures also breaks rock, counted as mined).

2. **10x Scrolling Sector (`4200 x 4200`) & Destructible Asteroid Clusters (`js/asteroids.js`, `js/grid.js`)**
   - **Asteroids are made of round NODES, drawn so overlapping nodes merge into one solid shape** (a bright rim on the outer edge only, a dark bevel, a raised top face; interior nodes are flat top face). Every one of the `clusterCount` (44) clusters is a **solid mass** of small nodes (`MASS_NODE_*`) accreted into one irregular piece (blob, ridge or lobed lump) in a range of sizes (`MASS_REACH_*`), with ore in short **seams**; `rockDebris` (40) small groups and single nodes sit between them. **Mining phases** (Deep Rock Galactic style): a mass is drawn solid until the claws or an elite bite into it; the node being ground, and the neighbours of every node that breaks, come **free** and are drawn as their own rock (the classic look) until they break in turn, so the mined edge crumbles into loose chunks. **Every node breaks at the same rate** (the classic rock's HP whatever its size; each vein type its classic HP); ore odds scale with node area against the classic rock (`ROCK_REF`, less `MASS_PACKING` overlap; one `MASS_CORE_CHANCE` deep-core roll per mass), so the field pays about the same ore as the classic ~930-rock field (gold ~135, shield ~65, cores ~8 per sector). Each asteroid/clump is a **draw group** rendered from a few shared Path2D fills (rebuilt only when one of its nodes breaks or comes free; plain rock painted before ore), so rock drawing costs about what the old per-rock strokes did.
   - Shattering rocks unearths hidden veins: **Gold Veins** (`goldVeinChance` 15% of rocks; drop `goldPerVein` ◆ gold coins, the run currency below, + rare buried Relic Chest roll), **Shield Crystal Veins** (`+25 Shield HP`), and **Deep Core Veins** (`+1 ❖ Void Core`, near cluster centres).
   - **Gold, REROLL & LOCK (`js/gold.js`; tuner group *Gold, Rerolls & Locks*)**: gold is a per-run currency (starts at 0, separate from Void Cores) shown on the HUD and in the level-up modal. Gold coins are solid glowing hexagons (XP geoms are hollow diamonds), give no XP, are magnetized like Void Cores and are yours whether your claws or an elite broke the vein. In a level-up hand, **REROLL** (`[R]`, controller X or the focusable button) replaces every unlocked card using the normal hand rules (loadout gating, NEW WEAPON odds and pity, rarity rolls) for `goldRerollCost` (20) × `goldRerollGrowth` (2)^n within the hand: 20, 40, 80… and back to 20 on the next level-up. **LOCK** (`Shift+[1-3]`, controller Y on the focused card, or the 🔒 toggle) costs `goldLockCost` (5), one card at a time: the locked card holds its slot through rerolls; pick another card and it returns, still locked, in the next hand in place of one random card (`rollHandAround` wraps `rollLevelUpHand`), until you take it or unlock it (no refund). A carried lock that is no longer valid (maxed, weapon discarded, NEW WEAPON with no free slot) is dropped with a note. On a **NEW WEAPON pick**, REROLL swaps the 3 weapons on offer for others (weapons just shown only return when too few are left; off when every unequipped weapon is already on offer) for `goldWeaponRerollCost` (40) × `goldRerollGrowth`^n within the pick: 40, 80, 160…; locks and banishes are off there. **SKIP** (`[K]`, controller LB twice (LB is also dash, so the first press only arms it), or the ⏭ button) takes no card and banks `goldSkipReward` (10) gold, half a first reroll so it is never a gold farm; a locked card carries into the next hand as if another card was picked. There is no SKIP on NEW WEAPON picks, the forced CHOOSE A WEAPON pick or Breakthroughs. Supply caches are unaffected. `npm run balance` reports gold per minute, per level-up and rerolls per run.
   - **Bedrock (unbreakable rock)**: pale violet rock made of nodes like the asteroids (`oreType: 'bedrock'`). Nothing breaks it: not the drill-claws, elite grinding, boss portals or blasts. It blocks the ship, enemies and shots like any rock; elites steer round it instead of plowing through, and the claws never reach for it. Mineable rock may coat it but is never buried in it, and bedrock is drawn over the rock round it, so a core always shows; it never counts toward replenishing. API: `addBedrock(x, y, r)`, `addBedrockClump(cx, cy, size)` (a random blob, ridge or branching arms), `addBedrockWall(points, width)`, `addBedrockBorder()`, then `rebuildSpatialHash()`. Every generated sector is walled in by a rough bedrock border (`bedrockBorder`; the glowing boundary line is only drawn where there is no wall, e.g. the Weapon Range) and gets `bedrockFormations` (7) clump slots (70-200 px), each filled with `bedrockFormationChance` (0.7), kept 900+ px from the start; `bedrockWrapChance` (85%) of clumps get a mass grown onto them (in place of one regular cluster), so the bedrock is the asteroid's hard core, visible from the start. Mineable rock keeps `BORDER_GAP` from the wall; the radar skips the wall (its frame is the wall).
   - **Space-Time Rifts (`js/rifts.js`; tuner group *Space-Time Rifts*)**: every 25–45 s (`riftIntervalMin`–`riftIntervalMax` after the last one sealed; the first after `riftFirstDelay`, 30 s) a rift tears open `riftSpawnMin`–`riftSpawnMax` px from the ship: a jagged crack splits into a lens of swirling void that drags the grid and sparks into it, then seals after `riftOpenTime` s. Fly into it and the ship is sucked in spinning, the camera cuts to a random clear spot on the far side of the map (round the entry's mirror point, at least 1500 px away), and an exit rift spits the ship out. The pilot has no control and the ship is invulnerable for the jump, plus `riftExitInvuln` s after. An edge arrow and a radar ring point to an open rift. None in the Weapon Range. Dev tuner: **⟁ Open Space-Time Rift**.
   - Bottom-right **Tactical Sector Radar Minimap** displays asteroid clusters, rich ore veins, bedrock, enemies, bosses, open rifts, and Relic Supply Caches.
   - Camera-culled **Hooke's-Law Spring-Mass Warping Neon Grid** (`js/grid.js`) ripples from explosions and funnels into gravity wells at 60+ FPS.

3. **Emergent Swarm Archetypes (`js/enemies.js`)**
   - **Boid Swarmers** (Magenta Diamonds): Flock using separation, alignment, cohesion, and swirl.
   - **Weavers** (Emerald Darts): Sense incoming player fire and dodge perpendicular to bullet trajectories.
   - **Pinwheels** (Violet Rotating Squares) & **Splitters** (Golden Hexagons that fracture into 3 fast mini-triangles).
   - **Veteran forms** (`VETERAN_TYPES` in `js/wave-plan.js`): swarmers, pinwheels, weavers, splitters, mini-splitters and mayflies grow an extra edge at waves 11 and 21 (+7% / +14% speed); tier-3 splitters burst into four.
   - **Vortexes** (Crimson Singularities, internal type `blackhole`): Funnel the grid, swirl enemies, pickups and sparks inward, bend passing shots, and tug your ship. The tug on your ship is a share of its own thrust: 50% at the pull rim, rising linearly to 75% at half the radius and holding there (`blackholePlayerPullEdge` / `Inner` / `InnerAt`, `playerPullShare` in `js/gravity.js`). Stacked vortexes are capped at the larger share (never above 80%), so holding away always escapes. Strengths live in the tuner's *Gravity Wells & Singularities* group.
   - **Combat-breadth archetypes (`js/archetypes.js`)**, introduced on boss waves (`UNLOCK_WAVE` in `js/wave-plan.js`) and announced once per run by a cyan *NEW HOSTILE SIGNATURE* card:
     - **Bruisers** (wave 10, orange pentagons with a ram): slow, durable, take ¼ knockback and survive ramming you. They wind up for 0.8 s on a marked lane (it locks for the last 40%), charge ~250 px, then vent for 0.9 s — the punish window.
     - **Gunners** (wave 20, chartreuse cannons): hold ~380 px, strafe, and after a 0.6 s aim line fire slow plasma orbs (`js/enemy-bullets.js`: pooled, slower than your ship, blocked by asteroids, absorbed by the hull-hugging shield via `shieldTouches`, ignored during a dash, wiped by Supernova).
     - **Aegis Shielders** (wave 30, azure hexagons): three front plates turn toward you slowly and stop projectiles; flank them or use missiles, lightning, orbitals, singularities or novas.
     - **Blinkers** (wave 15, orchid stars): collapse for 0.6 s while a ring marks the landing point, then teleport to your flank (130–250 px away, never into rock) and lunge.
     - **Conduits** (wave 40, aqua relay pylons): hang back and beam-link up to 4 allies (−30% damage taken, +20% speed). Kill them first.
     - Durable hulls show a brief HP ring after each hit so "this one takes longer" reads; fodder still pops.
   - **Campaign hostiles (`js/hostiles.js`)**, same contract as the archetypes: **Mayflies** (wave 5, lime specks in clouds of 12+, snap to a new heading within ±72° of the ship every 0.12–0.38 s, one hit each), the **Hulk** (wave 25, the old Prismatic Dreadnought hull as a slow, sturdy, 300×-scale-HP sponge), the **Borer** (wave 15, `js/borers.js`: a bronze drill-nose that mines through rock at `borerMiningMult` (3×) the elite base; within 520 px it aims a dashed lane for 0.9 s (locks red for the last 0.35 s), then bore-charges down it at 7.5 px/tick grinding at `boreMiningMult` (30×) and ramming through what it grinds (`e.boring` skips the rock push-back); while its drill is in rock (`e.grindT`, set by `AsteroidManager`) it spits 3 slow gravel shards at the ship every 0.9 s; HP 95 × wave scale), the **Hatchery** (wave 35, `js/hatcheries.js`: a slow scarlet honeycomb hive, HP 240 × wave scale, sturdy, that creeps to ~380 px and breeds **Hatchlings**: within 950 px of the ship, every 4.5 s a ring closes on it for 1.4 s while 2 egg pods swell, then they hatch; at most 6 of its brood alive, 24 in its life (the pods on its rim show what is left), never into the last 24 slots of the enemy budget; hatchlings circle the ship ~125 px out, brake and flare a dashed tick for 0.4 s, then dive straight through at 7 px/tick and pop on contact (0.45× contact); kill the hive and its whole brood withers in a 0.08–0.5 s cascade; off-screen it gets a HIVE edge arrow once it has hatched), the **Lancer** (wave 45, `js/lancers.js`: closes to ~330 px, aims a dashed line for 0.9 s that locks red for the last 0.3 s, then sweeps a 560 px beam 40° to one side over 0.85 s; any `e.beam` burns the ship for 1.4× orb damage via the contact loop), the **Repulsor** (wave 40: a 125 px field that swings the ship's bolts outward via `Game.repelProjectiles`, guarding whatever stands in it; each new bolt turned drains 1 of 12 charge, then the field overloads for 2.5 s; missiles, arcs, blasts and orbitals ignore it), the **Mitosis Cell** (wave 35: grows to 1.8× size and HP over 7 s, then splits in two, until 26 are on the field), the **Laser Gate** (wave 30, `js/gates.js`: two pylons and a beam round a hub; shoot the hub to break it, fly through the beam to detonate it for a 220 px blast of 90 × wave-scale damage to every hostile, bosses included, free for the pilot; the pylons hit like a hull; `Game.gateContact`/`detonateGate`), the **Carrier** (wave 20: hangs back ~430 px and launches 2 homing **Drones** every 3.2 s, up to 6; drones turn at 2.6 rad/s and burn out without a reward after 7 s), the **Kestrel** (wave 15, `js/squadrons.js`: a V of 3, later 5, amber darts flying strafing runs at 4.6 px/tick behind a leader; wingmen hold V slots off its heading and scatter onto solo runs when it dies) and the **Serpent** (wave 10, `js/serpents.js`: a head winding in S-curves trailed by 8 body plates that follow it like a rope; only the head can be hurt, the plates block shots (`deflect`: no damage, Supernova-proof, auto-aim prefers the head) and sting on contact; a dead head unzips the body plate by plate through `EnemyManager.doomed`, which the game drains through its normal kill path).
   - **Lieutenants (`js/lieutenants.js`)**: one per non-boss wave (from wave 2, `lieutenantDelay` s in), an elite of an unlocked archetype with a generated name/epithet (e.g. `QUAARC — THE MANIFOLD BRUISER`) and 1–2 modifiers (*armored* −40% damage, *hasted* +35% speed, *regenerating* 3% HP/s after 1.5 s unhit, *splitting* into 3, *shielded* front plates). Silver rank brackets and modifier arcs (never the boss's gold crown), a floating mini HP bar, a radar dot + `LT` edge arrow, and a small arrival/defeat card. HP is 40% of that wave's boss HP (×0.85–1.5 by archetype heft); they survive Supernova (−40% max HP) and contact. Reward: +1 Void Core (outside the per-wave cap), gold XP geoms and 8× score. Lieutenant kills use the elite kill tier. **Supernova bomb pickups** (v0.46, `BOMB_DROP` in `js/main.js`): a lieutenant drops a gold star pickup 35% of the time (void wells 4%, hulks 2%, all × Luck, none while you carry 9) worth +1 bomb; it replaced the spare bomb on Geom Attractor.
   - **Elite mining** (`js/pursuit.js` `eliteMiningDps`, `AsteroidManager.grindRock` in `js/asteroids.js`; tuner *Enemy Variety & Lieutenants*): lieutenants and bosses grind through asteroids at your base drill speed: `miningSpeed` (75/s) × `eliteMiningMult` (1.0), read live (bosses × `bossMiningMult` 4, serpent heads × `serpentMiningMult` 2 via `miningDpsFor`; serpent body plates skip rock entirely; a boss portal blasts every rock within `bossPortalBlast` 280 px on arrival via `AsteroidManager.blastRocks`, so boss spawn points ignore rock), with none of your mining upgrades or meta bonuses. They skip the rock-detour steering and plow straight at the ship; rock still blocks them while they grind, so a plain rock (about 70–100 hp at default size and hp tuning) holds an elite for about 1–1.4 s. Contact rule: rock within 6 px of the hull and on the ship's side of it, at most 2 rocks per elite at once (the two most squarely in the way), found through the same spatial-hash query the rock pushout already makes. The rock flashes and cracks exactly as under your drill; sparks and rock chips spray from the contact point (scaled by `vfxIntensity`, the occasional glow flash also by `vfxLinger`), and a quiet throttled scrape plays (fading out ~900 px from the ship). A rock an elite breaks goes through the normal shatter path (effects, sound, radar, cluster regrowth) and drops its normal ore (geoms, deep core, gold-vein geoms and chest roll) for you to collect; it does not count toward your rocks mined, a crushed shield crystal heals no one, and Tectonic Claw Bore only blasts on your own drilling. `eliteMining` (ON/OFF) switches it off, and elites then steer round rock like every other chaser.
   - **Pacing**: waves advance every 22 s (`waveLength`, *Difficulty Ramp* tuner group, with the HP, pack-cadence, pack-size, contact/orb damage and kill-XP ramps) with continuous spawns. **The 50-wave campaign** (`js/wave-plan.js`): every wave has a theme (banner name + pack-weight biases, e.g. *MAYFLY BLOOM* triples mayfly packs; past wave 50 two earlier themes are remixed); new hostiles only debut on boss waves. Packs (`js/waves.js`: `WAVE_PACKS`, `pickWavePack`, `packRoster`) are chosen by tunable weights × the theme bias. **HP budget** (`hpBudget`, `hpBudgetMin`/`Max`): the seconds between packs are scaled by (mean pack HP now) ÷ (mean pack HP under the pre-campaign v0.33 table), so every wave brings the same HP per second as before however the mix changes. While a boss wave's boss is warning in or alive, packs come at `bossPackRate` (70%) of their rate, only until that wave ends. Bosses keep priority on free enemy slots.
   - **Scoring** (`js/score-bonus.js`): a kill pays its enemy score × the multiplier (+0.1 × XP multiplier per Geom; a hit cuts it to 75%). Two flat bonuses reward progress without diluting clean play: the **wave bonus** pays 1,000 × wave² for every wave survived (wave 10: 100k, wave 50: 2.5M; 42.9M over the campaign, more per wave in Endless; wave 50 pays at SECTOR CLEAR) and the **VICTORY bonus** pays 100,000,000 once when the campaign is won. Sized on the live board: the W59 win (108M) had scored below a W33 run (121M); with the bonuses it is 275M vs 133M, while an x838 no-hit W42 run (892M) still tops both. The results screen (and the VICTORY screen) show the breakdown under FINAL SCORE.
   - **Bosses (`js/bosses.js`)**: a MINOR boss on waves 5, 15, 25, 35, 45 and a MAJOR boss (1.8× HP, 5 Void Cores) on 10, 20, 30, 40, 50 (`BOSS_SCHEDULE`). Boss HP is the Dreadnought formula × `bossHpMult` × `campaignBossHpMult` (default 2, named bosses only: lieutenants and boss XP ignore it); **Wave 50 is the FINAL STAND** (`js/final-stand.js`): it has no timer; The Prism arrives with a surge of `FINAL_STAND.surgePacks` (8) extra packs, then regular spawning (packs and lieutenants) stops. Once The Prism is down, clear every hostile (35 s after its death the stragglers beyond 360 px are drawn toward the ship at 260 px/s; at 90 s whatever is left is wrecked, so the ending never stalls). The last kill sounds **SECTOR CLEAR** (the music drops out under a sub-bass hit), and 2.5 s later the run pauses on a gold *VICTORY* screen (`js/victory.js`, state `VICTORY`) with **∞ CONTINUE FOR HIGH SCORE (ENDLESS)** (the run goes on at wave 51 after a 3 s lead-in, spawning back on, and the score keeps counting; ENTER after a 0.8 s grace, Ⓐ on a pad) or **END RUN** (ends the run via `triggerGameOver({ victory: true })`: the results read *VICTORY*; a pilot who won and later falls in ENDLESS gets *CAMPAIGN WON* on theirs). In ENDLESS, past wave 50, a minor wave fields two minors and a major wave a major plus a minor. leads a V of 6 Kestrels on strafing runs (line up, straight pass, overshoot 420 px, U-turn), drops a slow mine out of each side every 0.28 s of a run, calls back up to 2 lost wingmen per run; at half HP the escort scrambles and each run opens with a 5-orb fan; dies in a ring of 10 orbs. **Hive Carrier** (wave 20, major, core at 0.6× major HP): a slow mothership with 4 mounted launch bays (`PART_STATS.hive_bay`, `updateMount`: parts ride a fixed spot on the hull, have their own HP at 25% of the core's, launch drones, survive Supernova like elites and pop when the core dies); while any bay stands the core is shielded (`deflect`); with every bay down it spins up, sprays a double spiral of orbs and launches 2 gunner pods every 7 s. **Event Horizon** (wave 25, minor): a living black hole and a gravity well of its own (`gravityWell`, `pullRadius` 400, shot bend ×2.2; every well consumer reads `pullRadiusOf(w)`): tugs the ship under the usual escape cap, drags other hostiles in and swallows them to heal 2.5% each, inhales for 1.6 s every 6 s then exhales a ring of 16 orbs; Each one is a staged event: a `bossWarningTime` (default 3 s) warning with a hazard strip countdown, klaxon, music drop, red screen frame, radar ring and off-screen arrow to the reserved spawn point; then an arrival shockwave and title card (e.g. `BROOD QUEEN — MOTHER OF THE SWARM`), a gold-crowned silhouette, and top-of-HUD health bars (up to 3 stacked, `+N MORE` beyond). A kill triggers a fixed-tick hit-stop + half-speed slow-mo, gold flash and a reward banner. Sandbox `+Boss` runs the same event, cycling through the ten bosses on each press.
   - **Elite entrances** (`eliteOnscreen`, `eliteSpawnMinDist` 380, `eliteEntranceTime` 2.6 s, `eliteEmergeTime` 1.2 s): lieutenants and bosses materialize ON screen at least `eliteSpawnMinDist` from the ship (lieutenants over `eliteEntranceTime`, bosses over `bossWarningTime`), with a rift (converging spokes, an opening tear, a white-hot core), a deepening grid funnel, infall streaks, a rising charge rumble and a building shake; on arrival they emerge at 15% speed easing to full over `eliteEmergeTime` (white halo). Everything else keeps the off-screen ring below.
   - **Spawn placement & pursuit** (`js/spawn-placement.js`, `js/pursuit.js`; tuner group *Spawn Placement & Pursuit*): hostiles appear on a ring just outside the camera view (`spawnRingMarginMin`–`spawnRingMarginMax`, default 40–160 px past the screen edge, in world space from the camera rect and zoom). The ring is swept along the ship's motion for the warm-up so a spawn ahead of a running ship is still off screen when it lands; `spawnAheadBias` (50%) of spawns aim at the side you are heading, the rest use any side. Points outside the arena or in rock are rejected, so a ship on a wall gets spawns from the open sides. Packs reserve room for their formation so every member starts off screen. Only when no ring point is valid (or for Sandbox buttons) does a spawn appear on screen: at least `spawnMinDist` (260 px) from the ship with a `spawnOnscreenTelegraph` (1.4 s) warning (dashed hazard ring, sweeping countdown arc, the hull's outline growing in). No placed spawn materializes within `spawnMinDist` of the ship: it holds, fully charged, and after 1.5 s re-places off screen. Splitter fragments and *splitting* lieutenant copies are exempt (they burst where the parent died). Every chaser except an elite (which grinds straight through, see *Elite mining*) steers round rock that blocks its line to the ship (tangent detour via the asteroid spatial hash, no pathfinding), and an enemy that is off screen and more than `pursuitCatchupStart` (900 px) away moves faster, up to `pursuitCatchupMax` (1.8×) — so stragglers stream back instead of idling, and nothing changes speed on screen. Vortexes never chase. Lieutenants move `lieutenantSpeedMult` (+35%) faster than their archetype, capped at 90% of base ship speed so they stay dodgeable.

   - **Weapon levels, single-stat cards and Breakthroughs** (`js/weapon-levels.js`, formulas in `js/weapon-scaling.js`): every weapon, Autocannon included, goes from LV 1 (equipped) to **LV 18** (`WEAPON_MAX_LEVEL`). Each weapon has 4–7 stat cards (`STAT_CARDS`; the three sprayers have 7), and each card raises **only its own stat** plus the weapon level by its rolled jump (clamped at LV 18; a single card takes at most `CARD_MAX_RANKS` 11 ranks, so LV 18 takes a mix of cards). A UTILITY stat whose formula tops out (Grapple Hooks at the biggest hookable hull, Penetrator Core at 100% pierce keep, Sticky Gel / Deep Freeze / Etching Agent / Stun Coils at element rank 5) is capped there, and ACROSS THE BOARD's free ranks count toward that cap (`sharedCap` in `js/weapon-levels.js`, `levelRoom` in `js/upgrades.js`), so no card is ever offered a rank that does nothing; every stat formula reads only its own rank, and a card preview lists exactly that one stat. POWER stats add damage output: Damage ×`DAMAGE_GROWTH` (1.42, compounding) per rank, fire rate / reload / recharge / cooldown +`RATE_STEP` (40%) attacks per second per rank, count / salvo / chain / prism / wingmen add attacks, Sentry Turret reload speed adds turrets out, and vortex lifetime adds uptime. UTILITY stats (blast size, pull, core size, reach, range, orbit distance, spin, blade size, pierce, mine capacity and fuse) add no potential DPS (a wider orbit hits harder per pass to match). Every weapon has the same potential DPS at LV 1 and the same ×1.42 per Damage rank, so weapons built for damage stay equal (`tests/weapon-balance.test.js`). Deliberate exceptions live in `CARD_STEP_TRIM` / `LV1_TRIM` (`js/weapon-scaling.js`), each one tested: Autocannon Damage and fire-rate cards give 80% of the usual per-rank step (×1.336 damage, +32% fire rate; live player data, v0.36.1); Glaive Discs and Escort Drones take the same steps so they track the Autocannon at every level). `LV1_TRIM` scales a weapon's LV 1 hit damage and so its whole curve: offensive weapons are held level with the Autocannon's *real* output in the card benches (the potential model over-rates splash and burst hits, which overkill or miss), so Rocket Pods sit at ×1.5. Swarm Missiles: ×0.7 hit damage (×0.5 from v0.36.1 cut too deep; real runs had them far under the Autocannon) and `FIRE_RATE_TRIM` ×1.3, firing 30% faster at the same hit damage. Together 0.91 of the curve, ~1.82× their v0.42 DPS at every level, about level with the Autocannon at LV 1–6 in player data. Both are flat multipliers, so every card still changes only its own stat. Close-range defensive weapons (Shock Field, Orbit Blades) may sit a little lower. Escort Drones (×3.6) and Sentry Turret (×2.8) are trimmed to their class target (below). Graviton Mortar ×0.33: its gravity waves roll over whole packs, so on the shared curve it out-damaged the Autocannon ~2.5× in the pack bench; 0.33 holds it about even in total (see its entry below). **Class-based target** (Clay, v0.43.1; `WEAPON_CLASS` / `CLASS_TARGET`): a weapon's *realized* damage per target at equal level, as a share of the Autocannon's (aimed single-target, the 100% reference): automatic single-target (Drones, Turret) ~85%; area (Missiles, Rockets, Grenades, Gas, the sprayers, Tesla Arc, Mines, Vortex, Nanite Swarm) 60–70% per target and about even in total against a pack; close-range defensive (Shock Field, Orbit Blades) lower by design. `tests/weapon-balance.test.js` checks the automatic class in the card bench (85% ± 15% at LV 3 and LV 6; Glaive Discs and Escort Drones also at LV 12 and 18); the area and defensive targets are recorded, not enforced, until real enemies-hit-per-blast numbers are measured. Note the Autocannon realizes far more than the shared curve: 2 streams × 6.5 shots/s is 13× base damage per second at LV 1 against the curve's 3×, and Phase Piercer (a UTILITY stat in the model) adds 26–48% of its damage in mixed builds.    - **Tags** (`WEAPON_TAGS`; a weapon's chips are the union of its sources, `weaponTags` in `js/loadout.js`): blaster/helix/shrapnel `PROJECTILE KINETIC`, rocket pods `PROJECTILE EXPLOSIVE AREA`, orbit blades `ORBITAL KINETIC`, missiles `PROJECTILE EXPLOSIVE AREA`, arcs `ELECTRIC`, singularity `GRAVITY AREA`, dash nova `AREA`, tectonic blast `EXPLOSIVE AREA`, grenades `PROJECTILE EXPLOSIVE AREA`, gas trail `AREA CORRODE`, flamethrower `AREA BURN`, cryo sprayer `AREA CHILL`, acid sprayer `AREA CORRODE`, shock field `ELECTRIC AREA`, nanite swarm `DEPLOYABLE AREA CORRODE`, proximity mines `DEPLOYABLE EXPLOSIVE AREA`, sentry turret and escort drones `DEPLOYABLE PROJECTILE KINETIC`, Siege Battery shells `DEPLOYABLE EXPLOSIVE AREA`, rail lance `KINETIC`, glaive discs `PROJECTILE KINETIC`, claw harpoon `PROJECTILE KINETIC`, graviton mortar `EXPLOSIVE AREA`. Specialist cards boost every weapon with a tag and are offered once an equipped weapon (or owned passive) carries it: *Tungsten Penetrators* (+20% KINETIC damage/level), *Shaped Charges* (+30% EXPLOSIVE), *Overvolt Coils* (+30% ELECTRIC), *Field Amplifier* (+10% AREA size per rank, +15% before v0.46: every AREA weapon's blast, cloud, swarm, wave, field, pull or sprayer reach, plus the dash nova and drill blasts; the Claw Harpoon's slam and spin too). Like every card its rarity is its rolled level jump. Extra projectiles come only from each weapon's own count card (Prism Split, Tubes, Salvo Size, Bandolier, …).
   - **Elements** (v0.34, `ELEMENT_CARDS` in `js/weapon-levels.js`): Autocannon, Rocket Pods, Swarm Missiles and Plasma Grenades each have four element cards (the Tesla Arc had them too until v0.43.1; it is now always SHOCK, see `FIXED_ELEMENTS` below), e.g. *Autocannon: Thermite Rounds* (FIRE), *Cryo Rounds* (FROST), *Nanite Rounds* (CORROSIVE), *Shock Rounds* (SHOCK). They are offered **only in level-up hands** (`rollUpgrades(p, n, { cache: true })` and `eligibleUpgrades(p, { cache: true })` leave them out of supply caches). The first one taken **locks** the weapon's element (`req`: no other element of that weapon is offered again, and no cache, card or Breakthrough changes it); more cards of the same element are rank-ups (max 5). Every rank raises the weapon's level by 1 like a stat card (it counts toward LV 18 and the LV 6/12/18 Breakthroughs). The rank lives in `player.weapons.<weapon>_<element>`; a hit applies the element of the weapon behind its source (`SOURCE_WEAPON`: helix bolts are Autocannon, Storm and EMP arcs are Tesla arcs). **Stacks** (v0.40, Deep Rock Galactic: Survivor style; `js/status-effects.js`, numbers in `js/weapon-scaling.js`): every hit adds `stacksPerDamage` (10) stacks per base damage dealt (the hit before armor, corrosion and crits) × `elementPotency(r)` (1 + 0.25·(r − 1)) × Status Potency. Stacks are uncapped; every 0.5 s (`statusTick`, per-enemy clock that starts a full interval after the first stack) they act, then 20% wear off (`statusDecay`), and below 1 stack they are gone, so a stack lives 5 ticks on average and a weapon's DoT is a fixed share of its own hit damage (`statusDotShare`). Stacks follow damage, not a flat count per hit, so fast light weapons and slow heavy ones build statuses equally for equal damage. **BURN** (FIRE): `burnPerStack` (0.007 × base damage) per stack per tick (35% of a hit's damage at rank 1); a burning enemy with 5+ stacks has a 25% chance per tick to set the nearest enemy within 36 px of its hull alight with half its stacks. **COLD** (FROST): no damage; slows up to `chillSlow(r)` (30% + 5%·(r − 1); bosses 40% of it) in proportion to cold / the freeze threshold (cold worth 30% of the target's max HP; lieutenants ×1.5, bosses ×3). Each tick it may FREEZE (35% × pressure², certain at the threshold): frozen enemies stop and can't attack for 1.2 + 0.15·(r − 1) s (bosses/lieutenants keep 20%/50%), take +25% damage, then the cold is spent and they can't freeze for 1.5 s. **CORRODE** (CORROSIVE): an acid tick (0.0035 × base per stack) and +0.4% damage taken from every source per stack (DoTs included), capped at 30% + 7.5%·(r − 1). **SHOCK**: every hit is a zap stun of 0.12 + 0.02·(r − 1) s, or with chance 20% + 3%·(r − 1) a 1.2 s stun (no refresh while stunned, 0.75 s immunity after; lieutenants keep 50% and are immune 1.5 s, bosses 20% and 3 s). Shock stacks only hurt while the target touches another enemy (hull gap ≤ 6 px): each tick it takes 0.0035 × base per stack and conducts 35% of its stacks into up to 4 touching enemies with fewer, zapping them; shocked targets get +0.15% crit chance per stack (max +20%). DoT ticks are credited to the weapon that applied the stacks (`burn_<weapon>`, `corrode_<weapon>`, `shock_<weapon>`; damage-number sources `burn` / `corrode` / `shock`). Overlays are batched strokes per frame (burn ring, frost spikes growing toward the freeze, an ice-shell hexagon when frozen, corrode gauge toward its cap, faint sparks while charged, yellow crackle while stunned, conduction and spread arcs); invulnerable hulls are immune. **Built-in elements** (`FIXED_ELEMENTS`): Gas Trail (CORROSIVE), Flamethrower (FIRE), Cryo Sprayer (FROST), Acid Sprayer (CORROSIVE), Electric Shield Field (SHOCK) and **Tesla Arc (SHOCK, v0.43.1: it's lightning)** take no element cards; their element counts like an infused one (STATUS cards, Amplifiers, Supercritical, HUD tag). The Tesla Arc's SHOCK rank follows its level like the Gas Trail's (`fixedElementRank`: 1 at LV 1, +1 at LV 6 / 12 / 18), so it needs no extra card. Like every element, its status damage stays outside `POTENTIAL_DPS`, so the Tesla Arc's curve is unchanged.
   - **STATUS cards** (category STATUS, `statusCardWeight` 0.7, never raise a weapon's level; offered in hands and caches once an equipped weapon carries a matching element): *Status Potency* (+15% stacks per hit, every element), *Status Reactions* (id `status_application`: +5% fire-spread chance, −8% freeze threshold, +5% corrode cap, +2% long-stun chance per rank; any element), *Status Duration* (stacks wear off 5% slower per rank, never below half the base decay, freezes +10% and stuns +5% longer; any element), *Shock Conductor* (+4% long-stun chance, +10% stun length, +5% of the stacks conducted per rank; SHOCK) and the *FIRE / FROST / CORROSIVE / SHOCK Amplifiers* (+15% hit damage per rank for weapons of that element, and their DoT ticks too). Long-stun chance is capped at 60%.

## Game modes

Pick the mode next to **LAUNCH** on the title screen (click, `[1]` `[2]` `[3]`, or LB / RB and the d-pad on a controller); the choice is remembered on this device and RELAUNCH keeps it. Every rule lives in one table, `MODES` in `js/modes.js`, read through `modeRules(game | player | id)`; the modes run on the same simulation. HARDCORE and BLITZ runs wear a badge on the HUD and the game-over screen, and the pause menu's run overview names the mode. The Weapon Range always flies NORMAL.

- **NORMAL**: the standard run.
- **HARDCORE**: the shield is your only life. No shield regen, no shield cards (cards flagged `shieldCard`, today Shield Capacitor, are never offered in level-up hands or caches), no repairs (the relic cache's +45, shield crystal veins, the ALL SYSTEMS MAXED full repair), and the Void Armory's Aegis Shield Matrix is ignored, so every run starts at the base 75 shield (`BASE_SHIELD`). Every other armory upgrade applies; hit invulnerability is unchanged.
- **BLITZ**: a quick run that plays out in under 10 minutes. Its `tuning` overlay (shorter `waveLength`, a cheaper XP curve, and the enemy HP, spawn and damage ramps compressed into the shorter clock) is put on `TUNING` at run start (`applyTuningOverlay` in `js/config.js`) and taken off at game over or on the title. Saves, the cross-tab sync and the dev-tuner check read `baseTuning()`, so a BLITZ run never persists BLITZ values and isn't treated as dev-tuned. Tune it with `npm run balance -- --mode blitz` (see *Balance simulator*). At release (7 strategies × 4 runs, 20-minute cap) BLITZ runs lasted a median 7:31 (longest 12:18) for the expert bot and 5:54 (longest 9:17) for the average one, against NORMAL's 20-minute cap and 12:27.

Each mode has its own global boards and its own top 8 in MY RUNS (below).

## Global leaderboard

The title and game-over boards share scores between all players through a **Netlify Function** backed by **Netlify Blobs**. Both are built into the Netlify site this game already deploys to: no extra account, API key or Netlify UI setup is needed. The browser game itself still loads no third-party code.

**How it works**

- `netlify/functions/scores.mjs` is served at **`/api/scores`** (functions v2, `config.path`). `netlify.toml` points `[functions]` at `netlify/functions`; Netlify installs `@netlify/blobs` from `package.json` and bundles the function with esbuild alongside the static `dist` publish.
  - `GET /api/scores?version=<v>` → that game version's board; `GET /api/scores?version=all` → the all-time board (also what a bare `GET /api/scores` returns, for clients from before versioning). Add `&mode=hardcore` or `&mode=blitz` for that game mode's boards (no `mode` = NORMAL; anything else is a `400`). Answer: `{ version, mode, current, versions, entries, total, boardSize }` where `entries` are the top 50 runs, each `{ id, name, score, wave, level, kills, multiplier, time, date, version }` (`time` = seconds survived, `date` = server time, ISO, `version` = game version or `null` for pre-versioning runs) and `versions` lists the versions that have runs, newest first. An unknown `?version=` is a `400`.
  - `POST /api/scores` with a JSON run `{ name, score, wave, level, kills, multiplier, time, version, mode }` (`mode`: `normal`, `hardcore` or `blitz`, exactly; absent = NORMAL, so older clients still work; anything else is a `400`) → `201 { accepted, onBoard, rank, allTimeRank, version, mode, id, name, censored, entries, ... }` (`rank` and `entries` are for the run's own version board); `400` malformed, `413` too big, `415` not JSON, `422` implausible or unknown game version, `429` cooldown (with `Retry-After`), `503` too much write contention, `405` anything else. Responses are `no-store`; there are no CORS headers (the game calls its own origin).
  - **Versions**: the function imports `CHANGELOG`/`GAME_VERSION` from `js/changelog.js` / `js/version.js` (esbuild bundles them like `js/leaderboard-rules.js`). Any changelog version from `VERSIONED_SINCE` (0.9.0) on is accepted, so a run from an older cached client lands on its own version's board; anything else is a `422` (the game shows *OUTDATED GAME VERSION // RELOAD*). A run with no `version` at all (a client from before versioning) is accepted onto the all-time board only.
- **Preview builds race on a test board** (`netlify/lib/deploy-context.mjs`): Blobs stores are site-wide, so Deploy Previews and branch deploys used to post to the live boards. Each request now opens its store by deploy context (`context.deploy.context`, else the `CONTEXT` env var): `production` uses `leaderboard` / `stats` exactly as before; `deploy-preview`, `branch-deploy` and `dev` use `leaderboard-preview` / `stats-preview` (one shared test board for every preview). A preview's GLOBAL tab therefore shows only preview runs.
- **Storage layout** (Netlify Blobs store `leaderboard`), each board one JSON blob `{ version: 1, updated, entries }` holding the top **100** runs, with at most **5 per callsign**:
  - `board-v1@<version>` (e.g. `board-v1@0.9.0`, plus `gameVersion`): one board per game version, created by its first run. A new version starts empty, so old high scores can't crowd it out.
  - `board-v1`: the **all-time** board. It is the pre-versioning board kept as it was: its old runs have no `version` and show as `pre-0.9`, and every new run is merged in with its version.
  - `board-v1-hc` / `board-v1-hc@<version>` and `board-v1-blitz` / `board-v1-blitz@<version>`: the same pair of boards for HARDCORE and BLITZ runs. NORMAL keeps the keys above unchanged.
  - `ratelimit/<hash>`: per-IP cooldown stamps.
  - A run is written to its version board first (that's the rank the game shows), then to the all-time board (best effort: if that one stays contended the run still counts). Each write re-reads the blob and writes it back with `onlyIfMatch: <etag>` (or `onlyIfNew` for a board's first run); on a conflict it re-reads and retries with jittered backoff (up to 8 tries), so simultaneous submissions all land.
- The logic lives in `netlify/lib/leaderboard.mjs` (storage-agnostic, unit-tested with an in-memory store); `js/leaderboard-rules.js` holds the callsign alphabet and the list of board versions shared by browser and server, so the game never sends a name the server rejects.
- In the browser, `js/leaderboard.js` fetches with a 4.5 s timeout (6 s for submits). Offline, on the local `npm start` server (no function: `/api/scores` is a 404), or on a slow network, GLOBAL falls back to MY RUNS with an OFFLINE note; nothing blocks play or throws. Runs flown with the dev tuner/sandbox (or saved non-default tuning) are not submitted.

**Abuse protection (casual, not bulletproof)**

- Every field is type-checked and range-checked; integers are floored, multiplier/time rounded; unknown fields are dropped; bodies over 2 KB are refused.
- Plausibility envelope, fitted to the headless balance sim's best god-mode run (wave 41, level 78, 19.8k kills, 2.05 billion points in 894 s) and widened 3-10x, then re-checked for the 50-wave campaign and ENDLESS (30-minute god-mode sim runs to W66-72 and the live board's best sit 60x+ under the score bound): wave must match time survived (one wave per 22 s, or the mode's `waveLength` for BLITZ, ±1; from wave 50 on the wave may lag the clock, since the FINAL STAND has no timer, but never run ahead of it); kills ≤ 60/s + 100; level ≤ 10 + time/4; multiplier ≤ 1 + 8 × kills; score ≤ min(600 × t^2.5, 60 × (kills + 20)²) + 50,000 + the progress bonuses the wave allows (`waveBonusTotal(wave)`, plus the 100M VICTORY bonus from wave 50; `js/score-bonus.js`). Bounds are `PLAUSIBILITY` in `netlify/lib/leaderboard.mjs`; widen them there if balance changes push real runs past them.
- Callsigns: trimmed, upper-cased, 1-18 of `A-Z 0-9 space _ - . / ! ? # * + : '`. A small profanity filter (whole words, plus substrings after stripping punctuation and leetspeak) replaces offensive names with `CENSORED PILOT`.
- Rate limit: one submission per client IP every 20 s, stored as `ratelimit/<sha256(salt:ip)>` with a conditional write (so a burst of parallel requests can't all pass). Raw IPs are never stored. Set an optional `LEADERBOARD_SALT` environment variable in the Netlify UI to make the hashes unguessable from this public repo.
- **Scores are reported by the browser, so they can still be faked.** Anyone can read the bounds above and POST a believable run, or edit the game in dev tools. The checks only stop obviously impossible numbers, malformed data, junk names and spam.

**Running it locally**: `npm start` has no function, so the board shows OFFLINE (by design). To exercise the real API, run `npx netlify dev`, which serves the site plus `/api/scores` with a local Blobs sandbox.

**Moderating / resetting the board** (there is deliberately no delete endpoint):

- *One-time callsign purge*: add `{ id, names }` to `PURGES` in `netlify/lib/leaderboard.mjs`. The first `/api/scores` request after it deploys removes those callsigns from every board of every mode, then writes a `migrations/<id>` marker so it never runs again (later runs under those names are kept). `purge-madking-nox-v1` cleared the developer's test runs.

- *Netlify UI*: open the project, go to **Blobs**, pick the `leaderboard` store, and delete `board-v1@<version>` to wipe one version's board or `board-v1` to wipe the all-time board (each is recreated by the next run). `ratelimit/…` entries are disposable and can be deleted at any time.
- *Netlify CLI* (`npx netlify link` first):
  - reset one version: `npx netlify blobs:delete leaderboard board-v1@0.9.0` (all-time: `board-v1`)
  - remove one cheater: `npx netlify blobs:get leaderboard board-v1@0.9.0 > board.json`, delete their entries from `entries`, then `npx netlify blobs:set leaderboard board-v1@0.9.0 --input board.json`; do the same for `board-v1` (their runs are on both)
  - inspect: `npx netlify blobs:list leaderboard`

## Gameplay stats (RUN REPORT + anonymous balance data)

Every run is measured in-game (`js/run-stats.js`, a few counters per hit) so balance decisions can rest on data: is a weapon underperforming the others at the same level, which enemies kill players, which cards nobody picks.

**What is tracked** (per run, in the browser)

- **Weapons:** effective damage (overkill excluded) and kills per weapon, with sub-sources kept attributable: `burn_<weapon>` (FIRE burn ticks) count for the weapon that lit them, `helix` (Pulsar Helix) for Autocannon, `collapse` for the Vortex Singularity, `storm` (Storm Protocol chains) for Swarm Missiles, `siege` shell bursts for the Sentry Turret, `emp` (EMP Grenades arcs) for Plasma Grenades, `gas_pocket` / `gas_shroud` (Volatile Pockets, Toxic Shroud) for the Corrosive Gas Trail, `fieldlash` / `thunderclap` (Arc Lash and Thunderclap Overcharge) for the Electric Shield Field. Non-weapon damage has its own groups (`shrapnel`, `nova`, `tectonic`, `supernova`, `hazard` = a dying Vortex's burst, `ram` = enemies popping on the shield). The mapping comes from each weapon's `tagSources` in `js/loadout.js`, so a new weapon is attributed with no stats change; an unknown source id is its own group. Time owned, the weapon's level timeline and, **per weapon level**, seconds at that level, damage, damage in units of base damage, the damage and kills of *all* sources in the same window (share while at that level) and `DPS_TARGET(level)` from `js/weapon-scaling.js`.
- **Enemies, per type** (`boss` and `lieutenant` are their own kinds): spawned, killed, spawn → death time, damage dealt to the ship, hits, and the kind that landed the fatal hit.
- **Cards:** offered vs picked per card id (a locked card is counted once per hand), rerolls, locks, NEW WEAPON offers vs picks and which weapon was chosen.
- **Run:** game version, duration, wave, level, score, kills, the time of every level-up, gold earned/spent, final loadout with levels.

**RUN REPORT**: the game-over screen opens on a RUN REPORT tab (next to ARMORY): headline numbers, damage by weapon as bars with % share and DPS while equipped, and the top threats with the final blow marked. Rows are controller focus stops; the panel stacks at phone width.

**Privacy and the upload** (`js/stats-client.js` → `POST /api/stats`, `netlify/functions/stats.mjs` + `netlify/lib/stats.mjs`)

- The summary holds no callsign, no IP, no device or account data: only the numbers above. The server re-validates it (`js/stats-rules.js`: known fields only, ids `[a-z0-9_:.-]`, every number clamped, list sizes capped, body ≤ 16 KB, the version must be in `js/changelog.js`) and stores it as one blob per run.
- Rate limit: one upload per client every 15 s, keyed on `ratelimit/<sha256(salt:ip)>` exactly like `/api/scores` (same optional `LEADERBOARD_SALT`). Raw IPs are never stored.
- Not sent: runs flown with the dev tuner/sandbox (the leaderboard's *tainted* rule), runs under 20 s, and anything while the player has **SHARE ANONYMOUS STATS: OFF** (pause menu; stored as `vexolith_share_stats` in localStorage, default ON; blocked storage just means the default each session). The report's last line says what happened (SENT / OFF / SHORT RUN / DEV TUNER / OFFLINE). Offline, on `npm start` (no function) or on a timeout nothing blocks or throws.

**Endpoints and storage** (Netlify Blobs store `stats`)

- `POST /api/stats` → `201 { accepted }`; `400` malformed, `413` > 16 KB, `415` not JSON, `422` unknown version / run under 20 s, `429` cooldown.
- `GET /api/stats/summary?version=<v>|all` → the aggregate (`js/stats-aggregate.js`), plus `versions` (versions with runs), `knownVersions`, `stored`/`scanned`/`truncated` and `computedAt`.
- `runs/<version>/<yyyy-mm-dd>/<random id>.json`: one blob per run, never rewritten, so there are no write conflicts.
- `summary/<version|all>.json`: the cached aggregate, recomputed on a GET once it is older than 10 minutes. A recompute follows `list()` pages (up to 20,000 keys) and reads only the newest 1,500 runs, 24 at a time, so it stays inside the function time limit.
- `ratelimit/<hash>`: disposable cooldown stamps.

**The summary** has, per weapon and level, mean DPS, damage share and kill share while at that level, `vsTarget` and the sample size (runs and seconds); per weapon a time-weighted `vsTarget`, `index` and `flag`; per enemy type kill time, shield damage share, damage per spawn and deaths caused (the top three are `deadly`); card and weapon pick rates; and the run shape: median / p90 run length and level, % of runs reaching **LV 50** and **30 minutes** (the targets), median time to LV 10/20/30/40/50, histograms, deaths by cause, gold per run.

**Reading the dashboard**: `stats.html` (published next to the game, `noindex`, linked only from the hidden tuner drawer, Shift+Alt+T → 📊 STATS DASHBOARD). It has two dataset slots, **A** and **B**: each is a live version (`all` or one game version) or a local JSON file, either a summary (`npm run balance -- --no-bench --stats-out sim-stats.json`, or a saved `/api/stats/summary` answer) or a `--json` sim output / array of run summaries (aggregated in the page). Put players in A and the sim in B to compare them side by side.

- *Weapon balance*: the design rule is that every weapon has the same **potential** DPS at the same level, `DPS_TARGET(lv) = 3 · lv^1.5` × base damage. `vs target` is the share of that potential a weapon actually realized. Real fights never land every attack, so all weapons realize only part of it; the rule says they should realize the **same** part. `index = vs target ÷ median(vs target of the curve weapons at that level)`: above **1.2** → **⬇ NEEDS NERF**, below **0.8** → **⬆ NEEDS BUFF**. Levels with fewer than 3 runs or 60 s of data are LOW SAMPLE and never flagged. Autocannon has no own level (its stats level is 1 + its upgrade levels) and is not on the curve, so it is shown but not flagged.
- Damage share by weapon (and the sub-sources), enemies (☠ DEADLY = top three by deaths caused), card pick rates, NEW WEAPON choices, run length / level histograms and level pace.
- Caveats: index compares weapons at the same level, but a weapon picked late meets denser waves; tag cards and crits boost weapons unequally; the balance sim's bot does not play like people. Treat a flag as "look here", backed by enough runs.

**Resetting the data** (there is no delete endpoint):

- *Netlify UI*: project → **Blobs** → store `stats`; delete `runs/<version>/…` blobs to drop runs (e.g. all of a broken version), and `summary/…` to force a recompute on the next GET.
- *Netlify CLI* (`npx netlify link` first): list with `npx netlify blobs:list stats --prefix runs/0.13.0/`, delete one blob with `npx netlify blobs:delete stats <key>` (loop over the listing to clear a version), and `npx netlify blobs:delete stats summary/all.json` to refresh the cached aggregate.

## Audio

Everything lives in `js/audio.js` (`SoundEngine`). The AudioContext is created on the first user gesture; master volume (HUD / pause slider, persisted), mute (`M`) and the tuner's music/SFX gains all keep working, and every method no-ops without an AudioContext (node tests).

**Sound effects: samples with procedural fallback.**
- 32 short samples in `assets/sfx/*.mp3` (~400 KB total, 44.1 kHz mono 96 kbps), generated with ElevenLabs Sound Effects for this game. `assets/sfx/CREDITS.md` lists the prompt behind each file.
- `SFX_SAMPLES` maps each file to the `play*` methods that use it, its level, a random playbackRate spread (±1–6% so repeats don't sound identical) and voice limits: at most `maxVoices` copies ringing at once and at least `gapMs` between starts, so autocannon fire, hits, pickups and drone shots stay rhythmic instead of stacking into mush.
- The samples are fetched and decoded once, after the first gesture. Until one is decoded, or if its file is missing or fails to decode, its method plays the original procedural WebAudio sound instead. To replace a sound, drop a new `assets/sfx/<name>.mp3` with the same name (keep it short, trimmed and normalized; tune its `volume` in `SFX_SAMPLES`).
- XP shards still climb a scale while you collect a streak (the sample is pitched up per pickup); the boss klaxon sample repeats three times over the procedural sub drone; the elite charge-up is pitch-fitted to the materialize time.

**Music: procedural synthwave.**
- A lookahead scheduler wakes every 25 ms and places every note on the AudioContext clock, so timer jitter never drifts the groove; after a hidden tab it skips missed steps instead of bursting them.
- Three songs in different keys and tempos (`SONGS`: NEON VECTOR in A minor, CHROME HORIZON in D minor at -6 BPM, MIDNIGHT GRID in F# minor at +6 BPM, around the tuner's base `musicBpm`), each with its own bass pattern, arpeggio and lead timbre. Each song is a form of 8- and 16-bar sections with their own chord progressions; songs rotate when a form ends (a run starts on a random one).
- Voices: four-on-the-floor kick, gated snare on 2 and 4 with a reverb send, rolling 16th-note resonant bass, lush pads (three detuned saws per chord tone), a lead arpeggio through a dotted-eighth feedback delay, plus 16th hats, claps, crashes and tom fills at high intensity. Bass and pads run through a pump bus that ducks on every kick (sidechain feel); a generated-impulse convolution reverb glues it together.
- Intensity layering from `setMusicState({ intensity, muffled, boss })` (decided on bar lines with hysteresis): calm = pads + bass, mid (≥ 0.36, reached as the first enemies arrive) adds the drums, high (≥ 0.6) adds the lead arpeggio and extra percussion. `muffled` (pause, level-up, caches, game over) low-passes the bus and drops hats and lead. A boss warning drops to kick + bass under the klaxon; a live boss swaps in a darker Phrygian section with the square-stab riff until it dies.

**Soundtrack files.** The game streams the Suno-generated soundtrack in `assets/music/` (see its `CREDITS.md`), listed in `SOUNDTRACK` at the top of `js/audio.js`: `menu` loops on the title screen, `run` is the in-game playlist in intensity order (every run opens on Geom Harvest and builds to Singularity, then cycles without the opener; 4 s cross-fades), and `boss` loops through boss fights (the run track then resumes where it left off). They stream through `<audio>` elements and the same music bus (volume, mute and the menu softening still apply); an analyser on the low band drives the grid's beat pulse. With an empty `run` list or a track that fails to load, the procedural score plays.

## Engineering checks

Requires Node.js 20 or newer; the game and the tests have no package dependencies (only the Netlify Function uses `@netlify/blobs`, installed by Netlify at deploy time). Run `npm test` for regression checks. GitHub Actions runs the same checks on pushes and pull requests.

The simulation runs at a fixed 60 Hz; rendering follows display refresh. Enemy neighbors, projectile avoidance, and primary projectile collisions use spatial queries. Enemy capacity includes active and pending spawns (default 200). Game and Studio share `js/ship-renderer.js`. Saved tuning and progression are normalized on load.

Optional browser check: install Playwright separately, then run `node tools/browser-smoke.cjs` (or supply an existing Playwright module path as its first argument). It uses an isolated headless Chrome profile; set `BROWSER_EXECUTABLE` to choose another Chromium executable. Local assets are supplied through request interception, so the test needs no running server or network. Screenshots are written to the current folder. `node tools/controller-smoke.cjs <playwright-module-path>` plays title → level-up → NEW WEAPON pick → pause (sliders, damage numbers, loadout discard + confirm) → Field Guide → Patch Notes → chest → game over with a simulated gamepad only. `node tools/leaderboard-smoke.cjs <playwright-module-path>` checks the global board offline (aborted API), with a slow API (timeout fallback) and against a faked `/api/scores` (tabs and VERSION selector by mouse and controller, versioned submit, GLOBAL RANK · version line), saving `leaderboard-*-smoke.png` screenshots.

Animation review: `node tools/frame-capture.cjs <playwright-module-path> --scene fly|blast|supernova|vortex|range --frames 30 --every 2` steps the real game a fixed number of ticks per frame (seeded, so a command always captures the same frames) and writes `frame-NNN.png`, a contact sheet `sheet.png` and `anim.gif` (ffmpeg) to `captures/<scene>/` (git-ignored). `--crop N` frames the ship, `--setup "JS"` runs extra code with `g` (Game) and `p` (player), `--range '{json}'` configures the Weapon Range scene, and `--hud` keeps the HUD. See the file header for every option.

### Balance simulator

`npm run balance` runs the real simulation headlessly in Node (no browser, no dependencies) with a scripted bot pilot: it kites away from threats with a ~200 ms reaction delay, aims with auto-aim, dashes when about to be touched or boxed in, fires a Supernova when low in a crowd, collects Geoms and caches, and has **no invulnerability**. `Math.random` is replaced by a seeded generator inside the tool only, so every run is reproducible from its seed (`<seed>:<strategy>:<index>`). The default (7 build strategies × 3 runs, 15 min cap, plus the card bench) takes about a minute on 4 cores and prints Markdown:

- **Survival** per strategy (time / wave distribution, what killed the ship), **damage dealt by source** (every `hitEnemy` source is discovered automatically; shared `other` hits are split into shrapnel, dash nova, tectonic bore, vortex burst, and Pulsar Helix / Storm Protocol are split from blaster / lightning), **damage taken by enemy type**, **level-up pacing**, **cores earned**, a per-wave **difficulty curve**, and **time-to-kill** per enemy type per wave band.
- **Card throughput bench**: each card alone at every level against a topped-up pack of wave-6 targets, in a static `pack` scenario and a `chase` scenario (targets chase a circling ship; leaks/min = how many reach the shield). Weapons are discovered from `UPGRADE_POOL` (a card is a weapon if installing it changes `player.weapons`), so new weapons are benched automatically.

Runs also report **level by minute**, **XP collected per minute**, the **gold economy** (rocks and gold veins mined per minute, gold per minute and per level-up, rerolls per run: the bot buys one reroll in any hand it can afford at the base cost) and the **loadout at the end of the run**. The `prospector` strategy picks cards at random but drills toward nearby gold veins when calm (a regular gold miner); `mining` is a full mining build. Strategies take NEW WEAPON cards and equip their preferred weapons (`weapons` in `tools/balance/strategies.mjs`); `focus:<weapon>` takes NEW WEAPON until that weapon is offered. `--weapon-focus` adds a `weapon:<id>` strategy for every slot weapon (it starts with that weapon when it is a run-start pick, otherwise takes NEW WEAPON until it is offered, then its own level-ups first) and a `start:<id>` random build per run-start pick; Breakthrough picks are a coin flip unless a strategy sets `breakthrough: 'transform' | 'boost'`, and the report lists them per strategy and per weapon. `--god` keeps the ship alive to measure XP and level pacing over a long run (pacing only; survival numbers are meaningless with it).

Useful flags: `--mode normal|hardcore|blitz` (fly a game mode), `--runs N`, `--focus` (adds a `focus:<id>` strategy for every upgrade), `--weapon-focus`, `--strategies a,b`, `--skill expert|average|novice`, `--meta R` (Armory ranks), `--max-minutes M`, `--tune key=value` (A/B any `DEFAULT_TUNING` value), `--weapon key=expr` (A/B any `WEAPON_SCALING` entry, e.g. `"orbitalRadius=lv => 80 + lv * 8"`), `--seed S`, `--no-bench`, `--bench-only`, `--json out.json`, `--stats-out stats.json` (the runs' gameplay stats in the `/api/stats/summary` format, for `stats.html`; the report also gets a *Weapon DPS vs DPS_TARGET* table). Example: `npm run balance -- --runs 10 --focus --no-bench`. Files: `tools/balance-sim.mjs` (CLI, worker pool, report), `tools/balance/harness.mjs` (headless game, bot, metrics, bench), `tools/balance/strategies.mjs` (build strategies). Findings and the first tuning pass are in [docs/BALANCE_REPORT.md](docs/BALANCE_REPORT.md).

Extended checks (optional Playwright dependency): `node tools/soak-validate.cjs <playwright-module-path>` runs a seeded ten-minute accelerated simulation plus crowded 720p/4K draw checks. `node tools/audio-validate.cjs <playwright-module-path> audio-validation.json` renders actual Web Audio buffers and checks finite/non-silent output, mute, output headroom and clock recovery. Set `BROWSER_EXECUTABLE` to an installed Chromium browser if needed. Raw machine measurements and screenshots are ignored by Git. See [VALIDATION.md](VALIDATION.md).
